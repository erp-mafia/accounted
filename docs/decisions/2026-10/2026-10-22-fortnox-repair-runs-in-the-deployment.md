[2026-10-22] The Fortnox supplier number repair (crm#1157, step 3a) runs inside the deployment through a one-off arcim-migration route, signed in with an MFA (AAL2) session and limited to a hard-coded operator user id, not through a bearer-token route or a copy of PERSONNUMMER_ENCRYPTION_KEY: the key exists only as a Vercel sensitive variable, which no one can read, and it must not leave the deployment. A token route would skip sign-in and MFA; a hard-coded id matches no user on a self-hosted instance. The route is removed once the repair has run.
