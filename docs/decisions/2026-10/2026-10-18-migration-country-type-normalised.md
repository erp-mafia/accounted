[2026-10-18] The migration reads a party's country once (partyCountry in the arcim-migration entity mapper) for the stored column, the legacy invoice stubs and the customer/supplier type, instead of typing from the raw provider value: Fortnox, Briox and BL send "Sverige"/"Sweden", which made Swedish parties non_eu_business (0 % export on new invoices) and EU names like "Estonia" non_eu instead of eu_business. A value the normaliser cannot read stays a foreign signal as before (an unlisted country such as "Argentina" must not default to Swedish VAT), alpha-3 "SWE" reads as SE (same rule as debtorCountryCode), and an empty country is stored as null rather than '' (as migration 20260903173000 did for old rows). The shared normalizeCountryCode was left unchanged: it also validates API writes. Existing rows are left to a separate, founder-run one-shot repair (crm#1294 follow-up).
