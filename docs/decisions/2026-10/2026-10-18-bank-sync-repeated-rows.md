[2026-10-18] A bank sync drops a row that repeats an earlier row of the SAME response (same non-empty bank id, booking date, amount in öre and description) before the occurrence-index external ids are built, in both the Enable Banking and the Open Payments mapper (crm#1295): Nordea paged one account's list unstably, serving rows twice and leaving others out, and every copy was stored as its own transaction; a stored copy then swallowed a genuinely new row in a later sync (reconcileStableExternalIds pairs an unbridged row by id alone). Rows without a bank id are never dropped (two equal payments are real), the bank id is compared only within one response (ids that change between requests stay irrelevant to the stored key), and reconcileStableExternalIds is unchanged: once no copies are stored, an omitted-then-returned row heals on the next complete fetch. Existing copies are a one-shot data repair (re-key, not delete: imported bank rows are never deleted), not code. No migration.
