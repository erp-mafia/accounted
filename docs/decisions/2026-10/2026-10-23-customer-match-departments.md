[2026-10-23] The migration customer matcher no longer takes an org-number or VAT-number match when the card's customer number and name both differ from the source customer's (crm#1398): the departments of one public authority share an org number and are separate customers, so the only hand-made card under that number is not all of them; a duplicate can now be merged, a wrong fold cannot be split. The same name still matches under the user's own numbering (crm#1294). Left as is: resolve_provider_migration_party's SQL org-number fallback, which can still adopt that card when the declined department commits in an earlier batch than the card's own (no Fortnox adoption in production history had a conflicting customer number).
