[2026-11-18] The support dialog gets an AI assistant on its own route (POST /api/support/ask), beside the form to a person, never in place of it: every company where SUPPORT_ASSISTANT_COMPANY_IDS says so, on trial and on every plan, with no built assistant first (founder decision). It reads and explains and never books: no write or staging tool is attached, and a request to do the bookkeeping is answered with how to do it by hand and where a bookkeeping assistant such as Claude is connected. What is on a page comes from the source, not from written how-tos: the build indexes the message keys each page and its components read (scripts/generate-support-page-texts.ts, generated and gitignored, so no pull request has to refresh it), and read_page / find_in_app resolve them in the user's locale for the pages the company's menu has. Chosen over giving a model the repository at question time (slow, costly, and it would describe code the user cannot see) and over a search index (a second thing to keep in step with the app). It reuses the question box's engine (lib/agent/ask) and tables under its own intent, created archived so the chat's list never shows them; the answer is streamed, the prompt is cached as one prefix shared by every company, and the per-user limit is 60 questions a day because a trial is open to anyone.
